## Seven-item mutation-gate packet for G/Amit

1. **Accounts/Region:** only `lab-dev`, `lab-poc`, `lab-qa`, `lab-sec` in `ap-southeast-1`. Before each future write, privately verify the exact account/role against the approved binding and that Config recording is active. No organization-wide deployment.
2. **Pack/version/operation:** `awsops-home-readonly-v1`, version `1`; proposed **CREATE** via per-account `config:PutConformancePack` with the reviewed YAML as `TemplateBody`. Describe the exact name first. If it exists with identical approved content, read back and do nothing; if content differs, stop for a new version and review. Do not update v1 in place. Do not use `PutOrganizationConformancePack`.
3. **Controls/canary:** the exact six managed identifiers in the table and manifest; the existing two are repeated in the pack and may incur duplicate evaluations until a separately reviewed transition. No rule beyond these six, no custom rule, no remediation configuration. The #62 M5 canary control/resource is **not selected and excluded from this M4 gate**; M5 requires its own exact later authorization.
4. **Minimal actions:** proposed per-account caller permissions are `config:PutConformancePack` scoped to the exact pack, `config:TagResource` for the required approved lifecycle tags, and readback (`config:DescribeConformancePacks`, `config:DescribeConformancePackStatus`, `config:DescribeConformancePackCompliance`, `config:GetConformancePackComplianceDetails`, `config:DescribeConfigRules`, `config:DescribeConfigurationRecorderStatus`). Privately verify the existing `AWSServiceRoleForConfigConforms` with `iam:GetRole`: AWS says `PutConformancePack` can create that role if absent, so **stop if absent** and request exact separate IAM-role authority. No `PutConfigRule`, `PutRemediationConfigurations`, `iam:PassRole`, SSM, Organizations or broad IAM grant is requested for this managed-rule/no-remediation template. [AWS API](https://docs.aws.amazon.com/config/latest/APIReference/API_PutConformancePack.html), [service authorization](https://docs.aws.amazon.com/service-authorization/latest/reference/list_config.html).
5. **Rollback/retention:** stage one alias at a time, preserve private before/after readback and template digest, and stop expansion on any failed deployment, missing rule, partial/unknown status or unexpected cost. For a new pack, removal uses `config:DeleteConformancePack` and deletes pack-owned rules/evaluation history; it is **not authorized by this packet** and needs separate exact cleanup approval after evidence export. Retain existing M3 organization rules and normalized evidence. Proposed review/TTL date: 2026-12-31; owner must approve exact retention and tags before create.
6. **Cost:** additional Config rule and conformance-pack evaluations are usage-billed, plus existing recording/storage costs. Illustrative only: 4 accounts × 6 rules × 50 evaluations/month = 1,200 pack evaluations; at the AWS example rate of USD 0.001/evaluation this is USD 1.20/month for pack evaluations alone. Singapore rates and real volumes must be checked before the gate. Proposed incremental ceiling: USD 10/month across the four accounts, with 24-hour and monthly cost readback; stop for an owner decision if projected above it. [AWS pricing](https://aws.amazon.com/config/pricing/).
7. **Exclusions:** no AWS write before explicit #62 gate; no remediation, automatic fixes, SSM execution, IAM/OIDC/Organizations/network changes, new public exposure, PROD/company, OLD demo, retained EC2, Lightsail, `vagent`, Issue #11/PR #13, or deletion. No account IDs, ARNs, resource names or private findings in public evidence.

After a separately approved create, wait for `DescribeConformancePackStatus` success per alias, require all six managed rules and their source identifiers, then read `DescribeConformancePackCompliance`/details and aggregator state. `INSUFFICIENT_DATA`, missing resources, stale or partial evidence remains unknown/degraded, never green. Record exact pack version/template digest, account/Region identity privately, costs, and rollback state. Only then plan a separate live-registry/agent expansion.
